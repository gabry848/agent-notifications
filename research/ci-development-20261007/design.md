# Preregistered CI during independent development

One Pi agent completes a dependency-free package catalog while real CI workers execute snapshot tests. The modes differ only in automatic delivery of CI facts: N uses the current journal notification extension; PA gets identical ci_status and ci_wait retrieval tools and a competitive adaptive-polling strategy. No mandatory per-turn polls, artificial delayed delivery, model wakeups or follow-up user nudges.

The fixed scaffold has three imperfect helpers and six independent feature requirements. Tests include CSV round-trip/invalid quoting, semantic versions, transaction rollback/deep copies, searching, dependency planning, transfer streams, HTTP and CLI. The final independent oracle checks meaningful end-to-end behavior. CI tests initial existing helpers and every changed watched module source revision; source trees are copied before execution and identified by SHA256. Current green results count only for matching source revisions. Jobs can complete out of submission order. No sleeps extend a job or workload.

CI groups: csv (also a source-integrity green job), version, catalog, search, graph, transfer, HTTP, CLI. Three initial helpers should fail and source-integrity should pass; missing feature groups run once their entry module exists. Initial simulated CI queue offsets from prompt submission are integrity 0 s, CSV 30 s, version 60 s, catalog 90 s. Subsequent source-revision jobs use a fixed 10 s queue offset from the source-change milestone. Queuing models CI scheduling, not artificial agent duration; actual tests execute after that offset. Queued/start/test completion/publication are logged separately. Property tests check deterministic cases without sleeps. CI errors are condensed but detailed logs and snapshots are preserved outside the agent's workspace. The agent sees the specification and public smoke tests, never the private oracle/reference sources.

Before inference: validate the reference against every group, verify the scaffold failures, run transport/status/wait fixtures and current journal projection prefix assertions. Record installed defaults and adapter source hashes. Workload and harness hashes freeze before the calibration. One calibration pair is separated from five measured pairs if feasible (three minimum, explicitly exploratory), ordered N/PA then PA/N alternately using seed 20261007 (no result-dependent changes). If calibration reveals an actual harness fault, preserve the attempt and amend/freeze the harness with reason before confirmation. Do not increase workload because a mode finishes quickly or loses.

Stopping: one initial prompt, agent natural settlement or 30-minute wall timeout. Stop all child processes, wait for already launched CI, execute independent final oracle and check immutable public files. A run is correct only when the final oracle passes, public files are unchanged and all current-snapshot CI groups have a terminal green result. Preserve wrong, failed, incomplete and provider-error attempts. Report paired percentage changes only for complete correct pairs, using PA as denominator; do not manufacture completed pairs by relabeling failures.

Primary outcomes: final correctness, complete useful wall time, CI finish to first exposure and verified useful correction, useful work while CI active. Secondary: model/API requests; full input, output, cached input, total tokens; empty CI queries, waits, stale/ignored/late observations and errors. Pricing/cache are diagnostic evidence only. This controlled study does not assume notifications must win and may be shorter than the desired 10–15 minutes; actual useful duration is reported.

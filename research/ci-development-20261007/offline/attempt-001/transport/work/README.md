# Package Catalog

Complete this dependency-free Node 24 application. Existing CSV, version and catalog helpers require regression acceptance from background CI. Implement useful features while CI runs. Do not change this specification, package.json or existing test files; add your own tests and usage documentation in new files.

## Existing contracts

`src/csv.mjs` exports `parseCSV(text)` and `stringifyCSV(rows)`. RFC4180-style comma-separated rows, quoted commas, escaped double quotes, CRLF/LF and newlines inside quoted fields must round-trip. Empty input yields []; a final record separator adds no empty record. Preserve spaces. Reject unclosed quotes and quotes in unquoted fields. Every value is a string.

`src/version.mjs` exports `parseVersion(text)` and `compareVersions(a,b)`. Versions have exactly three nonnegative integer components with no leading zero except zero. Optional prerelease components contain ASCII alphanumerics/hyphens, separated by dots; numeric components reject leading zero. No build metadata. Parsed form is `{major,minor,patch,prerelease:[string,...]}`. Compare numerically; release beats prerelease; numeric prerelease is below alphabetic, numeric values compare numerically, otherwise ASCII ordering; shorter identical prefix is lower. Return -1,0,1. Reject invalid versions.

`src/catalog.mjs` exports `createCatalog(seed=[])`. A record is `{id,name,version,tags,dependencies}`: nonempty string id/name, valid version, string tags, dependency id strings. Trim id/name, normalize tags to lowercase trimmed unique sorted values (discard empty tags); preserve dependency order but remove duplicates. Store/return independent deep copies. Methods: `list()`, `get(id)` (null absent), `add(record)` (reject duplicate id), `update(id,patch)` (reject absent/id changes), `remove(id)` (boolean), `applyBatch(operations)` (add/update/remove objects; all-or-nothing transaction). Reject malformed operations/records; unknown dependency ids are allowed at storage time. List by id using ASCII order. Failed writes leave all state unchanged.

## Features to build

1. `src/search.mjs`: `searchRecords(records,query={})` returns `{items,total,offset,limit}`. Case-insensitive trimmed `text` matches name OR id; `tags` require ALL normalized tags; `versionMin`/`versionMax` inclusive semantic version bounds; `sortBy` id/name/version, `order` asc/desc, default id asc; always break ties by id ascending. Default offset 0, limit 20; integers offset>=0, 1<=limit<=100. Reject invalid sort/order/paging; do not mutate inputs.
2. `src/graph.mjs`: `planDependencies(records,requestedIds)` returns dependency-first unique ids. Process requested ids in input order and each node's dependencies in stored order; DFS postorder. Reject missing ids and cycles, with an error mentioning missing id or cycle ids. `reverseDependencies(records,id)` returns sorted ids that transitively depend on id; excludes id; reject unknown id. Do not mutate inputs.
3. `src/transfer.mjs`: `exportCSV(records)` header exactly `id,name,version,tags,dependencies`; tags/dependencies pipe-joined. `importCSV(text,catalog)` parses/validates whole input then atomically adds all records; exact header required, duplicate ids reject, return added records. `exportNDJSON(records)` yields an async iterator of JSON string plus newline per record. `importNDJSON(chunks,catalog)` accepts async string/Buffer chunks with UTF-8 characters possibly split across Buffer boundaries, empty lines ignored, final line without newline allowed. Validate atomically; malformed JSON or record leaves catalog unchanged; return added records.
4. `src/server.mjs`: export `createServer(catalog)` returning an unlistening node:http Server. JSON HTTP endpoints: GET /health ->200 `{ok:true}`; GET /records with text, tags comma-separated, versionMin/Max, sortBy, order, offset, limit -> search response; POST /records JSON ->201 created; GET /records/:id ->200 record; PATCH ->200 updated; DELETE ->204; GET /plan?ids=a,b ->200 `{ids:[...]}`; GET /export.csv ->200 text/csv; POST /import.csv ->201 `{added:N}`; POST /import.ndjson ->201 `{added:N}`; GET /export.ndjson ->200 application/x-ndjson. Unknown route/id404, malformed input400 with JSON `{error:string}`, duplicate creation409. Limit request bodies to 1 MiB; oversize413. URL-decode ids. No unhandled rejection or process exit on bad requests.
5. `src/cli.mjs`: runnable `node src/cli.mjs <command> --file <JSON file> ...`. Commands list (JSON search envelope; optional --text, --tags), add (record from --record JSON), remove (--id), plan (--ids comma-separated), import-csv (--input path), export-csv. File is a JSON array, absent file starts empty. Writes use temporary file + rename only after full validation. Output JSON except export-csv; invalid input exits nonzero with stderr and leaves data untouched. --file is mandatory.
6. Add meaningful regression tests and `USAGE.md` covering HTTP, CLI, CSV/NDJSON and errors. All functionality must work together.
